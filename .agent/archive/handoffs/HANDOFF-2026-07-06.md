  via getattr; record_counter is idempotent on value and discards the embedding anyway).

  counters kept (4 content_revised + ~20 failure).

## Restart / ops cheatsheet
- Restart: `pwsh scripts/start-server.ps1 -Action restart` (or `stop` then `start`).
- Restarts are self-healing as of `09f6b10` (dead same-host owner reclaimed at boot). If a scheduler
  ever still shows `running: False` (e.g. a lingering lease from a *live* stray process), call the
  `force_scheduler_takeover` MCP tool, or clear it with
  `DELETE FROM scheduler_leases WHERE lease_name='maintenance_scheduler'` in
  `C:\Users\you\IdeaProjects\.agent\mcp_telemetry.db` then restart.
- Health: `GET http://127.0.0.1:8090/api/ready`; stats+jobs: `GET /api/stats` with
  `Authorization: Bearer <MENHIR_OPERATOR_KEY>`.
- Telemetry DB: `C:\Users\you\IdeaProjects\.agent\mcp_telemetry.db`. Neo4j: `bolt://neo4j.example.internal:7687`.

## merge_entity Cypher — FIXED (2026-07-06, `796ec9d`)
`CorrelationRepository.merge_entity` threw `CypherSyntaxError: Invalid input '|'` on every call
(`datetime() | toString`) and also used a nonexistent `json()` function (no APOC on this Neo4j), so the
correlation/dedup **merge path was entirely dead** — no entity merge ever completed. Unit tests only
asserted on a mocked `neo4j.execute`, so it was never validated against a real DB. Fix: serialize the
audit entry in Python (`json.dumps`) and store as a JSON string in `survivor.merge_audit`; split into
phase-1 (read snapshot) + phase-2 (mutate/bridge/delete); FOREACH bridging so an absorbed node with no
neighbors still deletes. Both queries EXPLAIN-validated against live Neo4j. Live as of restart -> pid 26992.

## Stale-lease-on-restart — FIXED (2026-07-06, `09f6b10`)
Root cause: serve-watch stops the old server with `subprocess.terminate()` = Windows `TerminateProcess`
(hard kill), skipping uvicorn's shutdown lifespan, so `scheduler.stop()` never released the lease; on a
fast restart the TTL had not expired either, so the new server needed a manual `force_scheduler_takeover`.
Fix: `SchedulerLeaseStore.try_acquire` now reclaims a still-in-TTL lease when the prior owner is a dead
PID **on the same host** (`_pid_alive`: `os.kill(pid,0)` on POSIX; `OpenProcess`+`GetExitCodeProcess`
with explicit ctypes signatures on Windows). Restarts are self-healing now — verified: server reclaimed
the dead pid's lease automatically, `last_forced_takeover: None`. **The manual-takeover step in the ops
cheatsheet is no longer needed for normal restarts.**
