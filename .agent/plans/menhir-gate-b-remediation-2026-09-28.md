## Proposed design and implementation sequence

1. **Pin the working baseline and regressions.** Reconcile audit-branch changes with current main; record the actual implementation base SHA and dirty state. Inventory each writer below from current callers, because the structural index reports a stale root. Add deterministic failing tests before changing behavior; use barriers, not sleeps, for concurrency.
2. **B-04/B-09 — incomplete scans and honest answers.** In `project_scanner.py`, make traversal errors explicit with `os.walk(..., onerror=...)`; fail the scan before publication on unreadable/disappearing required subtrees. Preserve the previous index and report the failed attempt through manual-ingest and watcher error paths. A deliberate file cap remains a partial scan: carry coverage through serialization and persist it, guard every absence-based file/directory/symbol/edge prune, and never interpret missing coverage metadata as complete. Review file-read/stat failures for the same loss-of-evidence rule. Bump the scanner fingerprint schema when coverage semantics change. In `mcp/tools/recall/query_structure.py`, apply the common qualifier to empty symbols, dependencies, documents, and affected-tests responses; preserve stale-root/unknown-path warnings and distinguish unknown legacy coverage from measured completeness.
3. **B-05 — order publication at the graph boundary.** Extend the existing project identity/fence path, not a process-local mutex. Issue a monotonic scan generation on `ProjectIdentity` **before scanning**, separate from identity-binding generation; carry both through detached work. At `memory_graph_adapter.write_project_structure` / `StructureGraphWriter.write_project`, acquire the project write lock in an explicit Neo4j transaction, revalidate identity and the current issued scan generation, and execute all structure mutations, prunes, and final fingerprint/coverage publication through that transaction. A stale/missing token refuses before mutation; a transaction failure rolls back. Never mint a token for a previously captured payload at write time. Preserve migration admission/release and lock ordering; publish success metadata last within the transaction.

   Thread this through manual `scan_and_write_project`, watcher `scheduler_tasks.refresh_structure_graphs`, `_background_symbol_rescan`, and direct adapter/repository callers. Fence fingerprint-match `refresh_indexed_binding` too. The deprecated payload path must present a valid pre-scan token or refuse; it cannot bypass ordering. Inspect `write_document` and shared-entity helpers: use the same project lock where they overlap scan writes. Low-level helpers require the admitted transaction context. A newer failed attempt may invalidate an older pending scan; report refusal and rescan rather than accepting old bytes. No wall-clock freshness comparison or timeout-based permission for an old writer to resume.
4. **B-06/B-07 — artifact lifecycle and replacement.** In `work_artifact_repository.py`, make `transition_status` a locked compare-and-set on observed type, status, and exact namespace. A zero-row update returns an explicit conflict, never `applied=True`; diagnostics may reread but must not retry a stale intent automatically. Use the same artifact locking discipline for `supersede_artifact`, including two contenders naming different replacements, so the existing atomic `new → old` edge/status operation cannot race an ordinary transition. Lock multiple artifacts in a deterministic order.

   General transition to `SUPERSEDED` refuses with guidance to the existing dedicated operation; update domain/API/MCP legal-action guidance together. Audit creation/import as well: `create_artifact` currently accepts explicit statuses. Fresh registration of `SUPERSEDED` without an explicit valid replacement must fail with an actionable unresolved-import report; preserve source bytes/raw declarations, never substitute an invented initial lifecycle or replacement. Frontmatter supersession resolution continues through the dedicated operation. Missing/unknown type or status fails closed. Existing inconsistent records are handled by the census below, not silently rewritten.
5. **B-08 — unambiguous TODO attachment.** In `TodoRepository.create_todo`, use the existing location normalizer and resolve the optional explicit/parsed project first. Within the edge mutation statement, collect distinct eligible candidates and create `REFERENCES_FILE` only when exactly one permitted target remains. With no project, zero or multiple candidates leaves the TODO saved and unlinked, with an explicit unresolved/ambiguous result through backend and MCP. With a project, never fall back to another project; conflicting project declarations remain unresolved. Apply this per normalized location and keep `HAS_LOCATION`, returned metadata, and graph edges consistent. Replace the post-write `LIMIT 1`; duplicate legacy entities must not become an arbitrary choice. Shared/default namespace visibility must follow the existing contract and never widen the caller's scope.
6. **B-10 and integration.** Rename the existing E2E-8 `delete_namespace(max_nodes=1)` criterion to describe namespace-delete cap refusal, retaining that test. Add separate genuine structure-cap and traversal-error regressions over an already indexed fixture; align the criterion inventory, reporter, and README. Integrate the three subsystems before the independent re-audit.

## Invariants and acceptance criteria

| Finding | Required proof at the authoritative boundary |
|---|---|
| B-04 | Inject an unreadable subtree after a complete scan: every prior file/directory and its symbols/relationships survives, fingerprint is unchanged, and the caller sees failure. A capped scan cannot prune unseen paths; a later complete scan can prune truly deleted paths. |
| B-05 | Force A-scan → B-scan → B-write → A-write across separate connections/processes: A refuses with no changes to B's entities, edges, fingerprint, coverage, or binding. Same-project overlapping writes serialize; different projects progress independently. Test interruption mid-write, rollback, restart, stale identity, missing token, and unchanged-fingerprint paths. |
| B-06/B-07 | Two legal transitions from one observed state yield at most one success. Race transition against supersession and two different replacements: terminal state survives and exactly one replacement edge accompanies successful supersession. Test wrong namespace/type, absent/legacy status, registration bypass, and injected rollback between edge/status operations. |
| B-08 | Two projects both contain `src/main.py`: omitted project saves an explicitly ambiguous/unlinked TODO, explicit project links only its file, and unknown/conflicting project links neither. Cover concurrent candidate changes at final mutation, duplicate legacy matches, multiple locations, namespace isolation, and restart. |
| B-09/B-10 | Table-driven empty answers cover complete, capped, traversal-failed/stale, and absent legacy coverage. Evidence separately proves namespace-delete limits and actual structural scan limits; a criterion cannot PASS from an unrelated operation. |

All new writes preserve identity, namespace, and existing migration fences. Accepted background ingest is not completed publication; stale/failure outcomes reach existing error reporting. Never derive absence, a replacement, or project ownership from incomplete evidence.

## Risks, migration, rollback, and alternatives

The publication transaction can increase lock duration: measure a representative capped project, bound transaction time, and test cancellation/deadlock recovery without losing atomicity. Splitting it into separately committed batches requires an independently reviewed fenced-generation publication design before implementation; it is not an implicit optimization. A write-only mutex allows old A to publish after B, and a preflight-only CAS leaves a race, so neither satisfies B-05/B-06.

**Bounded B-05 fallback if the transaction refactor is too large:** extend durable admission to an exclusive per-project lease acquired **before traversal** and held through completion; reject competing attempts rather than queue their captured scans. Every existing mutation statement must lock the project identity and validate its lease owner/fencing generation in that same transaction. Recovery revokes the generation before another owner starts; an expired holder can never resume writing. Mark publication incomplete before the first batch and successful only after the last. On interruption, retain an explicit incomplete state and require a fresh full scan; no partial result authorizes an absence-based prune. This fallback does not promise whole-publication rollback: test and document its partial-progress/recovery semantics, and obtain independent acceptance of that tradeoff before choosing it. It changes ordering, not the supported product surface.

New scan counters initialize under the project lock; absent legacy tokens refuse, and legacy coverage stays unknown until a successful rescan. Stop/drain old writer processes before enabling the new protocol; mixed old/new writers can bypass it. Prepare a **read-only census** of edge-less/multiple-replacement `SUPERSEDED` artifacts and ambiguous/cross-project TODO links, using disposable legacy fixtures now. Actual operator-corpus inspection/repair needs separate authorization. Record each observed anomaly's explicit disposition; do not claim existing-data conformance without evidence. No automatic relinking, lifecycle rewrite, graph migration, or #119 repair belongs here.

Rollback stops writers, preserves a graph backup/evidence, and returns to the prior binary only with vulnerable structure writes disabled; do not re-enable stale-write behavior against newly accepted state. Additive counter fields may remain inert. Existing records need no destructive migration. A correction to historical artifacts/TODOs is a separate reviewed repair with a before/after census and rollback receipt.
