Scalar Perception Roadmap

Three roles, three tracks: deterministic-first typed-scalar extraction (avoid the LLM call), ScalarStateView recall + authority (current-state, LLM-based), and Event Scalar / event history (categorical occurrences — purchased/acquired/attended). Different maturity, different gates — don't read one as another.

Current focus Track B just cleared a canonical 78-item benchmark and needs a promotion decision. Track C shipped all five phases today but only has small noncanonical evidence. Track A is not authorized to route or persist deterministically — its extractor barely fires on real text.
Why Track A says “not_evaluable,” Track B says “canonical,” and Track C says “noncanonical.” Track A's gates are pre-registered before capture and locked before any frozen run — never chosen after seeing results, and LLM agreement alone can't pass or fail one. Track B's canonical designation is a separate standard: one fresh, non-resumed run on tracked-clean worktrees against the full 78-item fixture, superseding all earlier development/diagnostic runs. Track C is fully implemented but deliberately evaluated only on small focused/canary panels so far — its own reports say plainly they don't replace a canonical KU78 run. Three different evidentiary bars for three different claims, none of them a stall.

Track B · ready for a decision

  • Canonical KU78 pass landed 2026-08-06, marked canonical this morning (2026-08-07). Scalar state/history + View authority, LLM-based, deterministic router off.
  • 68/78 (0.872) vs 6/78 (0.077) no-memory — a +0.795 lift, fresh non-resumed run, both repos tracked-clean.
  • Open: default-on decision for scalar_view_authority_enabled/scalar_history_enabled, and triage of the 10 remaining misses.

Track C · implemented, evidence still thin

  • All 5 phases landed today (commit 370eff1): perception, persistence, admission, recall authority, transport. Default-off, byte-compatible when off.
  • 230 event-focused tests, a clean 3-namespace canary, and a 5-case focused LME panel — every report self-labels noncanonical, explicitly not a KU78-scale claim.
  • Open: run this at canonical KU78 scale before any enablement conversation, same as Track B already did.

Track A · blocking promotion

  • Coverage collapse on real text. The router checkpoint's own 78-task fixture: 915 user episodes → 1 typed proposal → 0 deterministic bypasses, even with every known class hypothetically promoted.
  • Confirmed independently. The research adapter's frozen 78-task replay: 36 candidates → 0/36 composed (canonical), 1/36 composed (isolated path). Curated panels score 12–15/15; real conversational text does not.
  • Sample size. Per-class gate needs Wilson LB ≥ 0.99 at n ≥ 100. Panels top out at 24–48 cases total, not per class.
  • Unmeasured gates. Recognition, role/operation, performance, cache, replay on the dependency bridge are not_measured, not just unmet.
