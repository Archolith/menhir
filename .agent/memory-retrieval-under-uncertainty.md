# Read-time retrieval under uncertain relevance

**A design reference for a class of problem, not a feature.** The write-side counterpart is
`memory-aggregation-under-uncertainty.md`; this document does the same job for the read path: what
happens when a memory system must, at query time, select a small ranked set from a heterogeneous
store — entities, derived Views, fact edges, pending episodes, structural anchors — using relevance
signals that are noisy, incommensurable, and partly generated by retrieval itself. The mechanisms
live in `services/recall_service.py`, `services/scoring_service.py`, `services/hybrid_retrieval.py`,
`services/context_builder.py`, and the frontier oracle stack; this is the *why* and the *shape*.

---

## 1. The problem

A query arrives as a short string. The store holds tens of thousands of nodes of unlike kinds. The
job: return the few memories that answer the question, inside a token and latency budget, without
misleading. Three things make it hard, and they compound:

1. **Relevance is heterogeneous.** A candidate can be relevant because an embedding is near, a term
   matched exactly, a just-ingested episode links to it, a file under discussion anchors it, or a
   dated fact edge points at it. These signals live on *different scales* and are not comparable by
   arithmetic.
2. **The store contains its own hazards.** Superseded beliefs, stale Views, session-scoped
   scratch, unreviewed candidates, and cross-namespace bleed all look like memories; returning them
   is worse than returning nothing.
3. **Retrieval observes a system it also modifies.** Returning a memory reinforces it (recency
   touch, edge-weight increment), which changes what the next retrieval returns.

## 2. The governing asymmetry inverts at the read boundary

The write side abstains freely because **retrieval is its fallback**: a missing View costs latency,
not the answer. Retrieval has no such backstop — below it is nothing. So the asymmetry flips:

> **On the write side, a wrong commit is far worse than a missing one. On the read side, a missed
> answer is a hard failure, and a misleading result is a transient one.**

Neither failure direction dominates universally; which one matters is a property of the *query* and
of the *candidate's trust tier*. The architecture therefore splits the concern:

- **Recall is bought by adding candidate sources** (disjunctive generation — vector, BM25, pending
  provenance, file anchors, fact-edge pointers), never by loosening a gate.
- **Precision is bought by hard membership gates** (conjunctive filtering — scope, freshness,
  supersession, namespace, wardens), never by score penalties.

The mirror-image of the write side's law ("raise precision by adding a veto") is: **raise recall by
adding a source; raise precision by adding a gate; never tune one to fake the other.**

---

## 3. The load-bearing separation: sources carry provenance, one scorer ranks

Every candidate is stamped with its **source** (`CandidateSource`), and the source — not the score —
declares what its relevance number *means*:

- `VECTOR`/`BM25` similarity is a search score, gated by the noise floor.
- `PENDING`, `FILE_LINKED`, `FACT_EDGE` candidates are **injected by provenance**: their relevance
  is the fact of the link, carried as an explicit prior (`SOURCE_PRIORS`), and the cosine floor
  must not touch them (`FLOOR_EXEMPT_SOURCES`).

This is the read-side analogue of "perception probabilistic, fold deterministic": generation may be
messy and multi-channel, but scoring is **one pure function** (`ScoringService` — no I/O) over a
uniformly-shaped candidate, and every effect (access touches, edge reinforcement, rehydration) is
orchestrated at the edges where it can be disabled (`update_access=False` for measurement probes).

### The scale-coupling law
An additive relevance formula silently breaks when any input changes scale. The live example: the
0.15 "similarity floor" actually gates graphiti's RRF **rank** score (top dual-method hit ≈ 2.0),
not a cosine — it behaves as a rank cut and works "by luck of rank_const=1"
(`scoring_service.py:47`). The rule this teaches:

> **Never mix signals across a scale boundary without an explicit contract.** Either normalize at
> the boundary, or gate/weight per source. A threshold or weight tuned on one generator's scale is
> a latent bug against every other generator.

## 4. A taxonomy of read-side failure modes

### 4a. Scale coupling / incommensurable signals
A generator's score scale leaks into thresholds and weights tuned for a different scale (the RRF
floor; the unweighted similarity lane vs the ≤0.5 bonus lanes). Fails silently — ranking degrades
with no error. Guard: per-source priors and exemptions; scale contracts at every fusion point.

### 4b. Self-reinforcing relevance
Returning a memory touches `last_accessed` and increments traversed edge weights; recency and
prominence are scoring lanes; so **retrieval trains its own ranker toward whatever it already
returns**. Left unchecked this is rich-get-richer: early lucky hits become permanent winners.
Guards: reinforcement must be bounded and decaying; measurement paths must be pure reads
(`update_access=False`); prominence degrades to zero when its cache is unsynced rather than
inventing confidence. Verified 2026-07-03: edge weight increments are capped at 5.0 (+0.1 per
traversal), and decay is a v1 non-goal — edge lifecycle is deliberately tied to endpoint
lifecycle via the `last_accessed` touch, which indefinitely shields returned nodes from decay.

### 4c. Answer-shape mismatch
The answer lives in a shape the default search cannot see: a dated fact on an *edge*, an aggregate
in a *View*, a chronology across nodes. No amount of weight tuning fixes this — the candidate never
enters the pool. The fix is a **new source**, and the measured lesson is *how* to inject it:
edge-as-answer (standalone terse facts) scored net-negative because terse floor-exempt strings
crowd out rich nodes and collapse context; edge-as-**pointer** (hydrate the edge's endpoint nodes
into the normal path with an edge-derived prior) preserved node richness and fixed the ranking.

> **Inject pointers to rich nodes, not terse answers.** Use the sharp signal to *find*, return the
> full memory to *answer*.

### 4d. Staleness and supersession leakage
A superseded View version, an expired belief edge, or a memory whose code anchor has drifted
surfaces as if current. Guards are **hard membership filters**, not score penalties: `view_current
is False` excluded by default; belief invalidation (`expired_at`) filters temporal facts; the
belief/staleness gates flag or refuse on evidence. The residual: staleness nobody stamped.

### 4e. Context collapse at packing
Retrieval quality is finally won or lost in the prompt bundle. Known hazards: near-duplicate
dedup on short texts (Jaccard over tiny word sets is noisy) can drop the distinct-but-similar
answer; truncation buries below-the-fold hits; ordering matters and was measured — a Timeline-first
brief buries the answer, so **relevance order leads and supplements append below**. The bundle
composer is part of retrieval, not a formatter.

### 4f. Intent mismatch
One ranking formula cannot serve "what's the total" and "what happened first" and "what do I
believe now" equally. Guards: presets reshape lane weights per intent; a deterministic lens
classifier gates intent-specific sources (fact-edge hydration fires only on history-wanting
queries). Wrong-lens injection is a *regression*, not a no-op — sources displace better candidates.

## 5. Trust is structural, never scored

The read-side echo of "confidence is a gate, never a stored score":

- `CANDIDATE` scope is **never** recalled — approval promotes it; no score can surface it.
- `SESSION` scope is excluded by default; inclusion is an explicit caller decision.
- Superseded View versions are excluded by default; `include_superseded` is a provenance/debug
  affordance that labels them.
- Namespace membership is filtered defensively even after the search already scoped it.
- Write-side receipts (`view_audit_*`, `source_confidence`) stay **out of the surface, the
  embedding, and the scorer**. The scorer reads similarity, adjacency, recency, prominence,
  conflict, and type policy — nothing that a write-time process asserted about its own confidence.

A trust decision expressed as a weight can be out-tuned by other weights; expressed as membership,
it cannot. Tiers are cheap to reason about, compose monotonically, and are immune to scale coupling.

## 6. Promotion discipline: shadow → flag → default

No ranking change ships by argument. The ladder, as practiced:

1. **Shadow** — run the new mechanism observe-only on live traffic (the AssertionPipeline shadow
   attaches would-be decisions to the trace; results byte-for-byte unchanged; failures logged,
   never raised).
2. **Flag** — activate behind a tuning flag defaulting to today's behavior exactly; the active
   path must **fail safe to the shipped order** on any exception.
3. **Measure** — A/B on the oracle slice; record the number *in the code* at the decision site.
   Failed arms are kept, labeled with their measurement, for comparison (fact-edge standalone:
   "measured net-NEGATIVE at N=30, 0.300→0.033").
4. **Default** — only then flip.

Two corollaries. *Inert-combination warnings*: when flags interact (belief gate computes verdicts
only the warden gate applies), the inert combination logs a warning rather than silently doing
nothing. *Probe purity*: any measurement that reads the system must not reinforce it (4b).

## 7. Derived state competes; reachability is the delivered metric

Views enter recall with **no ranking privilege**: their only advantage is a surface engineered for
the queries they answer (`retrieval_text` bakes subject, measure, and value into the embedded
text). Whether a committed View actually surfaces for its query class is therefore an empirical
property, measured per-recall by the **view-reachability trace**: the rank and token-depth of the
first current View in the results — the delivered retrieval entropy for query-sufficient state.

This is the honest posture, but it leaves a known tension with the write side, whose governing
asymmetry assumes a stored aggregate "ranks authoritatively, surfaces at the top of recall". Today
that is an aspiration the read side measures, not a mechanism it enforces. The pending decision
(A6, deliberately out of the perception prod-wiring plan's scope) is whether an aggregate-lens
query should get **deterministic View injection** — the read-side twin of the write side's rank-1
promise. Until that decision lands, the two documents disagree, and the disagreement should be
resolved by measurement (reachability traces), not by assumption.

### Seam obligations (what the write side is owed)
- Receipts and confidence fields never rank and never render into surfaces — enforced at
  `ViewRepository.record` (kept out of signature and embedding) and honored here by never reading
  them in the scorer. Keep it structural on both sides.
- Superseded View versions never compete with current ones in default recall.
- When the write side's weaker claim rungs land (intervals, provisional tier, evidence sets), their
  **rendering contract binds the bundle composer**: constituents inline, the number subordinate,
  no midpoint summarization — the answering model flattens hedges harder than humans do, and the
  first reader of every recalled fact is the answering model.

---

## 8. Summary — the principles, portable

1. The write side's asymmetry **inverts** at the read boundary: a missed answer is a hard failure
   because retrieval is the system's last fallback. **Recall is bought with sources, precision with
   gates; never tune one to fake the other.**
2. **Sources carry provenance; one pure scorer ranks.** A candidate's source declares what its
   relevance number means; provenance-injected candidates are exempt from score floors tuned for
   search noise.
3. **Never mix signals across a scale boundary without a contract.** Thresholds and weights tuned
   on one generator's scale are latent bugs against every other generator.
4. **Retrieval modifies what it measures.** Reinforcement from reads must be bounded, decaying,
   and absent from measurement paths.
5. **Answer-shape mismatch is fixed by a new source, injected as a pointer to a rich node** —
   never as a terse floor-exempt answer that crowds out context.
6. **Trust is membership, not weight.** Scoped tiers, supersession, and namespaces are hard
   filters that no score can override.
7. **Shadow → flag → measure → default.** Active paths fail safe to the shipped order; failed arms
   stay in the code with their numbers; inert flag combinations warn.
8. **The context bundle is part of retrieval.** Dedup, order, and truncation change answers as
   much as ranking does; rendering contracts for hedged claims live here.
9. **Derived state competes, and reachability is measured, not assumed.** The write side's
   "ranks authoritatively" premise is delivered only if the read side chooses to deliver it —
   decide with reachability data, then make both documents tell the same story.
